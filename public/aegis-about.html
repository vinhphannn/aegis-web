01 / WHY AEGIS

The hard part is not one board. It is the system.

FCFlight core
RCOperator control
WEBConfiguration tools
MODExpandable modules

AEGIS started from building a flight controller and a custom radio controller.

But the deeper problem quickly became clear: a UAV is not one PCB, one firmware image or one algorithm. Flight control, radio, positioning, perception, power and operator tools all have to work together.

AEGIS is an attempt to build those layers with a shared architecture instead of treating every subsystem as a separate project.

Explore the ecosystem
FLIGHT CONTROL

AEGIS FC

A custom STM32H7-based flight-control platform developed as the core of the AEGIS ecosystem.

The current work focuses on reliable sensor integration, clean I/O architecture, PX4 support and a hardware platform that can grow with navigation and autonomy modules.

  • STM32H7 flight-control platform
  • Multi-sensor architecture
  • PX4 integration
  • CAN / UART / external peripherals
  • Designed for modular expansion
OPERATOR CONTROL

AEGIS Controller

A custom handheld controller developed alongside the aircraft rather than treated as an unrelated accessory.

Firmware, telemetry, controls and browser-based updating are being developed together so the operator side can evolve with the rest of the system.

  • Custom handheld hardware
  • Multi-channel control
  • Telemetry display
  • BLE simulator support
  • Browser-based firmware workflow
02 / THE SYSTEM

Different modules. One architecture.

AEGIS is being developed as a family of hardware, firmware and software modules. Each module should be understandable and useful on its own, while sharing interfaces and workflows with the rest of the ecosystem. Complexity belongs where it creates real capability — not everywhere by default.

03 / PRINCIPLES

Complexity has to earn its place.

  • 01

    Integrated, not tangled

    Subsystems should work together without becoming inseparable. A module should have a clear responsibility, interface and failure boundary.

  • 02

    Simple before clever

    A more sophisticated architecture is only useful when it solves a real engineering problem. AEGIS avoids adding layers, frameworks or hardware simply because they are possible.

  • 03

    Build, measure, improve

    Hardware is tested as hardware. Firmware is measured at runtime. User experience is judged in the browser. Decisions should come from evidence instead of assumptions.

“AEGIS is not about putting every feature on one board. It is about making every layer of the aircraft work as part of one system.”

AEGIS is still being built.

The current focus is turning working prototypes into reliable, reusable modules: flight control, operator control, radio, positioning, perception and the tools that connect them.

05 / THE BUILDER

Built by learning the whole stack.

I’m Vinh Phan, an embedded systems and UAV developer in Vietnam.

AEGIS grew out of my university UAV work, where I started by building a real-time flight controller and custom radio controller.

What began as a graduation project gradually expanded into a much larger question: how should the flight controller, radio, navigation, perception and operator interface be designed when they are treated as one system from the beginning?

My work sits between embedded hardware, firmware and autonomous robotics.

I design PCBs, bring up sensors and communication buses, work with real-time flight software, build control hardware, and experiment with navigation and vision systems.

AEGIS is where those pieces are being brought together.
